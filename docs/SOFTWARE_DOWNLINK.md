# AES 软下行数据域合同

状态：数据域核心已实现；AOS 完整帧布局及 GCM 认证的 AES 密钥更新指令待接入。

## 固定接口

星载 `dlsec_encrypt_data` 使用 AES-256-ECB 加密；地面
`downlink.DecryptData` 使用 Go 标准库解密。密钥恰为 32 字节，输入和输出
恰为 880 字节，即 55 个 16 字节分组。没有填充、IV、Tag、协商参数或
算法选择开关，错误密钥长度和数据长度均拒绝。

调用者持有一份有效 AES 密钥，模块不保存密钥或维护暂存槽。星务负责
密钥原子替换和持久化，且必须将替换与加密调用串行化。地面也只使用一份
有效 AES 密钥，切换期间的数据连续性由外部流程保障。数据域自身没有
密钥版本字段，解密端不能从数据域自动识别错误密钥。

ECB 只提供保密性，不提供认证、完整性或抗重放。重复分组产生重复密文；
篡改密文、错误密钥或重复数据可能照常解密。解密成功不代表数据可信。

## 缓冲区和密钥边界

C 接口支持输入输出分离和完全原地加密，拒绝部分重叠及密钥与输出重叠。
失败时清零可写输出前 `min(capacity, 880)` 字节；重叠的输入或密钥字节也
可能因此被清零。成功时只写 880 字节，调用方提供更大的容量不会扩大写入。
没有堆分配或可变全局状态，独立缓冲区调用可以并发。

C 在每次加密前使用公开 NIST 向量执行 KAT，失败即清零输出并拒绝加密；
重复调用也不能绕过仍然失败的自检。工作密钥展开、块状态和临时数组通过
volatile 写清零。SubBytes 通过固定运算的有限域求逆实现，不用秘密索引
查表；仍需目标编译器审查、真实板卡 WCET/栈和侧信道验收。

Go 返回新分配的明文，错误时返回 nil，不修改输入，也不将密钥存到模块
状态。Go 标准库 AES 没有显式销毁扩展密钥的接口，本实现不宣称 Go 运行时
或寄存器中的所有秘密副本已经擦除。调用方负责有效密钥和返回明文的生命周期。
接口及测试不记录真实密钥或业务明文。

## AOS 适配边界

明、密 AOS 帧均固定 1024 字节，字段布局相同。880 字节数据域的起始偏移
尚未冻结，因此本次接口只处理调用方切出的独立数据域，不解析或改写帧头、
尾部、FECF 或任何其他字段。调用方只有在布局冻结并完成帧级验证后，才能
将该核心接入完整帧处理链路。当前没有下行 HTTP 路由或持久化服务。

## 验证和后续接入

`make downlink-gate` 是独立数据域门禁，完整 `make release-gate` 必须包含它：

- 4 个 NIST SP 800-38A F.1.5 规范块逐一重复 55 次验证，保持块的规范期望值；
- 379 个独立 Oracle 数据域向量：全零、全 FF、递增、重复分组、256 个密钥
  单 bit 变化、55 个分组变化、64 个确定性随机样本；
- C 实际输出交给 Go 解密，逐字节对照独立期望；ARMv7/QEMU 同样执行；
- 非法长度、空指针、输出容量、边界哨兵、双向重叠、完全原地、KAT 故障、
  重复数据和 ECB 篡改属性；
- C/Go 各自覆盖率 >=95%，C 的 O0/O2 结果一致，ASan/UBSan、固定 seed
  4096 次 C 有界变异及 Go smoke fuzz。

向量是公开 TEST ONLY 材料，采用统一 18 列清单，包含规范来源、算法、参数、
预期结果及记录 SHA-256；文件 SHA-256 和生成器 SHA-256 同时校验。
独立 Oracle 固定为 pyca/cryptography 50.0.2 / OpenSSL 4.0.3。常规门禁只读
离线向量，重新生成遇到版本或规范 KAT 不符直接失败。

下一步通过 GCM 认证 TC 接入 AES 更新；必须同时验证权限、重放、原子提交
失败、断电恢复和星地生效时序，不能仅以指令编解码完成作为交付结论。

规范来源：[AES FIPS 197](https://doi.org/10.6028/NIST.FIPS.197-upd1)、
[ECB / NIST SP 800-38A](https://nvlpubs.nist.gov/nistpubs/Legacy/SP/nistspecialpublication800-38a.pdf)。
