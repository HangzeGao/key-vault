# TC GCM 帧格式与密钥管理

本文冻结地面 Go 与星载 C 的唯一遥控密码合同。普通 TC 使用 SM4-GCM 和 4 字节标签，Recovery 使用独立工作密钥的 SM4-GCM 和 16 字节标签。完整安全域保持 6 字节，密文起始偏移保持 11。AES 下行不属于本次修改。

## 帧编码

所有多字节整数使用大端字节序。完整帧最多 1024 字节，主导头 5 字节，FECF 2 字节，帧长字段为完整帧长度减 1。

| 偏移或字段 | 普通 Current 与 Next | Recovery 换根准备 |
| --- | --- | --- |
| 0～4 | 最终 TC 主导头 | 最终 TC 主导头 |
| 5～6 | 高 2 位选择值，低 14 位计数 | 固定 0xC000 |
| 7～10 | 4 字节 Tag | 32 位 Recovery 计数 |
| 11 起 | N 字节密文，N 为 16～1011 | 41 字节管理密文 |
| 密文后 | FECF 2 字节 | Tag 16 字节，再跟 FECF 2 字节 |
| AAD | 主导头与控制字，共 7 字节 | 主导头与完整安全域，共 11 字节 |
| 完整长度 | N＋13 | 70 |

Tag 为标准 GCM 完整标签的左侧 4 或 16 字节，不增加二次散列或私有认证变换。Tag 本身不参与 AAD；FECF 覆盖最终头、安全域、密文及尾随标签，不提供密码学认证。

普通关联选择值等于该关联的安全代次 mod 3。接收端依据持久 Current 代次，选择当前值或下一代次值；第三个普通值拒绝。选择值 3 专属 Recovery，控制字低 14 位非零时拒绝。选择值只用于定位候选密钥，不作为认证通过或切换依据。

例如 Current 代次 7 的选择值为 1，Next 代次 8 为 2；提升后 Current 为 8，未来 Next 为 9，其选择值为 0。每三代循环选择值，但完整代次及内部 SPI 继续变化。旧帧即使碰巧选中新关联，仍须通过新工作密钥的 GCM 认证与重放检查。

## 内部 SPI 与 nonce

SPI 为内部持久保存的 uint16 逻辑关联编号，合法范围 0x0000～0xFFFF，下一普通 SPI 等于当前加 1 后按 16 位回绕。它不再直接上链。安全代次为非零 uint32，提升严格加 1，不允许回绕；当前代次达到 0xFFFFFFFE 后停止提升。

两类 nonce 均为：

```text
NoncePrefix[6] || InternalSPI16BE[2] || Counter32BE[4]
```

普通 14 位计数以无符号数补足到 32 位。Recovery 使用独立前缀、完整 SPI、工作密钥和 32 位计数。相同工作密钥不得重复使用 nonce；地面必须持久分配，失败或丢失响应产生的跳号不回退。

## 密钥与派生

首装灌入 16 字节当前业务根及独立 16 字节恢复根；待生效业务根由认证的 Recovery 事务安装。根不嵌入生产代码。Current、Next、Recovery 各使用一把 16 字节 SM4 工作密钥，共 48 字节。GCM 的 GHASH 子密钥由算法内部计算，不作为额外配置项。

SP 800-108 Counter KDF 使用 SM4-CMAC，输入为 Counter32BE（从 1 起）＋Label＋0x00＋Context＋OutputBits32BE。两类输出均为 128 位。

| 用途 | Label | Context 顺序 |
| --- | --- | --- |
| 普通 | TC-GCM32-V1 | SCID16BE、方向码 1、套件 0x0003、完整 SPI16BE、epoch32BE、业务根版本32BE，共 15 字节 |
| Recovery | TC-GCM128-RECOVERY-V1 | SCID16BE、套件 0x0002、完整 SPI16BE、恢复根版本32BE，共 10 字节 |

没有 Pending 根时，Next 使用当前业务根和下一代次派生；有 Pending 时使用其根和版本。初始化与复位完成重复派生核对；收帧不逐帧重派生。提升后将 Next 工作密钥移为 Current，并派生未来 Next。工作密钥轮换可以保持业务根版本不变，换根则要求新版本严格大于当前。

## 短标签使用限制

普通 TC 密文与 AAD 总长最多 1018 字节，执行 [NIST SP 800-38D 附录 C 表 1](https://nvlpubs.nist.gov/nistpubs/legacy/sp/nistspecialpublication800-38d.pdf) 中总长不超过 1024 字节、单工作密钥最多 2048 次认证解密的限制。本项目采用该表的使用约束，不据此声明 SM4 套件获得 NIST 认证。

星载每帧最多重复验证两次。每次进入密码验证前，通过 AUTH_BUDGET 提交持久预留 2 次；首轮失败仍保留全部预留。Current 与 Next 各自保存已预留总额。总额为 0～2048 的偶数，剩余不足 2 时返回 AUTH_BUDGET_EXHAUSTED，不调用 GCM，不交付明文。重放检查提前拒绝的帧不消耗验证预算。

地面每工作密钥最多持久分配 1024 帧，从 0 到 1023，90% 告警，达到上限停止；这比 14 位计数容量更严格。星上认证失败和中断会提前消耗预算，因此 1024 是地面分配上限，不保证一定能接受 1024 个有效帧。地面须结合可信预算遥测安排切换。

32 位标签的认证保障受其长度限制。失败限额会被恶意流量消耗，存在拒绝服务风险；正常 TC 不因失败或耗尽自动切换。Recovery 保持独立的 128 位标签和重放状态，不消耗普通预算。

## 持久化与掉电

星务提供 load_state、commit_state，计时回调可选。密码模块不访问 NVM。状态记录格式必须绑定公开接口版本 5，拒绝缺失预算字段的记录。完整状态采用三副本、受保护提交锚和防回退检查，由实际 BSP 实现并验证。

| 提交类型 | 完整状态的原子变化 |
| --- | --- |
| AUTH_BUDGET | 核对所选完整关联身份，预算恰为已持久值加 2，仅保存该预算 |
| ORDINARY_REPLAY | 核对已预留预算不变，保存 Current 完整重放窗口 |
| EPOCH_PROMOTION | 原子提升 SPI、代次、根、重放；Next 预算移给 Current；未来 Next 预算置 0；清理 Pending |
| ROOT_PREPARE | 保存 Pending 和 Recovery 窗口；首次安装新根清空 Next 预算，同一事务重试保留预算 |

普通帧通常执行两个持久提交。预留未确认成功时不执行 GCM；预留成功后掉电，已扣预算保留。业务提交前掉电不推进重放和代次；业务提交后掉电恢复新状态，同一帧拒绝重放。回调结果不确定、失败或不合法时停收并重载可信状态。预算耗尽本身不全局停收，保留可用 Next 与 Recovery 路径。

每次候选写入保留旧锚指定版本，三副本完整核验后原子推进锚；不能把较旧多数当成当前状态。密钥、预算、重放和代次必须整体恢复，不能分别投票字段。物理擦写原子性、可信锚与存储寿命由星务集成验证。

## 工作密钥与根更新流程

地面根准备输出匹配的 PREPARED 记录及 Recovery 密帧。星上验证并保存 Pending 后，地面根据可信回报确认，执行受控激活，再发送首个合法 Next 普通任务帧。星上验证、检查任务规则、持久提升后交付明文。

地面提升时原子创建同根未来 Next 及独立计数。后续同根常规激活要求已观察到星上 Current 的 SPI、代次、根版本与地面一致，自检通过、任务摘要匹配、未停收、无 Pending 且 Next 尚有额度，防止发送侧连续超前；该检查依赖遥测来源可信性。激活产生的 ACTIVE 记录只表示密帧已经生成，不能证明星上已经接受。

普通发送达到分配上限后返回错误；由受控调度确认状态并激活 Next，禁止绕过失败自动重置计数。常规工作密钥轮换不增加空口管理指令。后续新业务根的受控导入仍属运维管理流程，普通 HTTP 不开放替换根的入口。

## 接口版本与验证

公开星载接口版本为 5，函数仍为 init、reset、receive、get_runtime_status；新增的是持久预算字段和 AUTH_BUDGET 提交种类。地面 SQLite schema 为 4，任务配置版本 2，星载状态观察版本 2，换根准备载荷版本 2。未知或过时格式直接拒绝，不保留兼容转换。

规范锚点使用 SM4 分组 KAT 和 RFC 8998 GCM KAT；独立 OpenSSL 向量、Go 与 C 差分、ARMv7/QEMU、真实 HTTP/SQLite/C 进程及中断注入共同验证。主机存储模型与合成任务规则不替代目标 BSP 掉电和正式任务规则验收。
